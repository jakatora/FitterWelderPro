# Visible calculator inputs for knowledge questions — 2026-10-22

Knowledge chat previously received the user question, history and optional numeric ISO summary, but no calculator inputs. This left questions such as “explain these parameters” context-free even though command interpretation could read the visible form. A new typed CalculatorQuestionContext captures explicitly allowed numeric/choice fields from the existing visible native InputToolHandle ports for heat_input, rolling_offset, pipe_slope and pipe_route. This is an incremental context contract; other modules and native result readback are not newly covered here, and the full assistant objective remains open.

Each module has an exact field allowlist. Finite numbers are copied, blank/invalid numbers become null, closed process/standard/slope-mode choices are validated, and pipe-route end_welds is boolean. Unknown fields, free text, accounts, records and calculated outputs are excluded. No numeric input is inferred, clamped or silently replaced by zero. The snapshot map is immutable. ToolBridge inputFields already requires a ready foreground handle and rejects popups.
